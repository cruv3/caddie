## Key concepts / terms

- **Action space** — restricted to GUI primitives: tap(coords), swipe(direction, distance), text-input, long-press, back, home. Deliberately mirrors human input modalities. (source: Abstract, Fig. 1, p.2)
- **In-context learning via exploration** — agent autonomously explores an app first, generating its own documentation of what each UI element does. No model fine-tuning needed. (source: §1, p.2)
- **Few-shot from human demonstrations** — alternative/complementary to autonomous exploration; user runs a task once, agent observes and writes documentation. (source: §1, p.2)
- **Knowledge document** — runtime artifact consulted before each action. Updates as exploration continues. Direct analog to Caddie's skill files. (source: §1, p.2)

## How I plan to use this in the thesis

- **Section**: Related Work (state of the art) + Discussion (positioning).
- **Role**: **Comparator and counter-example.**
- **Specific claims it supports**:
  - "AppAgent represents the autonomy-first design philosophy in LLM smartphone agents: high autonomy, learn-once-deploy-many, no runtime intelligibility."
  - "AppAgent's knowledge document is the closest existing analog to Caddie's skill files — same data format (procedural Markdown-ish text), same runtime consultation pattern, but generated by agent exploration rather than by the user."
  - "AppAgent's evaluation focuses on task-completion rate; it does not measure whether users could *intervene* or *correct* the agent mid-run. This is the gap Caddie addresses."
- **CCS concept worth citing**: *Human-centered computing → User interface management systems.* Positions AppAgent in the HCI literature, not the systems literature — which means the gap Caddie fills is an HCI gap, defensible at CHI / DIS / IMWUT venues if you ever submit a follow-up.
